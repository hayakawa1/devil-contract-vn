## 🎯 ファイル命名規則

### ルート開始ファイル
```
00_ルート開始.txt
```
- 各キャラルート固有の導入シーン

### 分岐ファイル
```
分岐A_○○ルート.txt
分岐B_××ルート.txt
```
- 分岐Aは中盤の重要選択
- 分岐Bは後半の決定的選択

### エンディングファイル
```
END1_ハッピー.txt
END2_ノーマル.txt（またはビター）
END3_バッド.txt
```
- ハッピー：最良結果
- ノーマル/ビター：中間結果
- バッド：最悪結果

## 🔧 ドッキング（統合）方法

### 手動ドッキング
1. 各ノードファイルを順番に読み込み
2. 「統合確認/」フォルダに完全版を生成
3. チャッピーがシナリオ全体の流れを確認

### 自動ドッキング（将来的に）
- Pythonスクリプトで自動統合
- フラグ管理に基づいて条件分岐を挿入
- Ren'Py/Unity向けにエクスポート

## 📊 メリット

### ノード分割のメリット
1. **並行作業が可能**：複数ルートを同時進行
2. **修正が局所的**：一部変更が全体に影響しない
3. **再利用性**：共通シーンを複数ルートで使い回せる
4. **バージョン管理**：Gitで差分管理が容易

### 統合確認のメリット
1. **全体の流れチェック**：プレイヤー視点で読める
2. **矛盾検出**：キャラの言動がブレてないか確認
3. **テンポ確認**：読み心地の最終調整
