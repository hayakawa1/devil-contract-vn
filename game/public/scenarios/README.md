# シナリオ運用メモ

## 契約ルール

- 悪魔の薬（一本目）による肉体変化は元に戻らない。
- ただし、変化後にどう生きるか、誰と向き合うかは本人たちの選択で変わる。
- 悪魔は「願いを叶えた」と言うが、本人の本音を断定しすぎない。本人に言わせる。
- 主人公の体は変わらない。変わったのは七人だけ。主人公は「原因を作った側」として責任を負う。

## 悪魔のゲーム（第1話で提示）

- **主人公の勝ち**：七人の誰か一人と「本物」になる（仮面も強がりも筋肉も全部見た上で、それでも隣を選ぶ）。
  悪魔は二人の感情を「ご祝儀」として一口だけ食べて去る。→ 各ルートの GOOD END。
- **悪魔の勝ち**：七人の誰かが、自分を捨てて「二本目」を飲む。二本目は体をさらに変え（stage2）、心ごと作り変える
  （迷わない・揺れない・傷つかない）。悪魔は主人公の感情をまとめて食べる。→ 各ルートの BAD END。
- **保留**：誰も二本目を飲まないが、「本物」にもならない。悪魔は何も食べられず、ゲームは続く。→ 各ルートの NORMAL END。
- 悪魔は二本目を、ヒロインがいちばん弱った夜に差し出す。強制はしない。いつも「選ばせるだけ」。

## 背景の使い分け

- `protagonist_room*` は主人公の部屋だけ。ヒロインの部屋には使わない。
- `friend_house` は高橋家（友樹・美羽の家）。結衣の家には使わない（結衣の家は外観＝`street_evening`、室内は語りで処理）。
- `school_gate` は主人公の学校の校門。冴の学校の前には使わない（`street_evening` か `station` を使う）。

## jump の使い分け

- 別ファイルへ移動する場合は `[jump storage="episode01.ks"]`。
- 同じファイル内のラベルへ移動する場合は `[jump target="label_name"]`。
- `glink` / `link` の `target` は同じファイル内のラベルを指す。

## 英語版

- 英語版シナリオは `public/scenarios/en/*.ks`。日本語版と**同じ構造**（ラベル・タグ・話者の並び）で、本文だけが英語。
- 言語はタイトル画面・設定画面の「日本語 / English」で切り替え（`?lang=en` でも可）。UI 文言は `game/i18n.js`、キャラ名・エピソード名は JSON の `*_en` フィールド。
- 日本語版を直したら、英語版は次の手順で作り直す（`game/` で実行）。
  1. `python tools/i18n_ks.py extract public/scenarios/xxx.ks > translations/xxx.ja.txt`（本文を行番号つきで抜き出す）
  2. `translations/xxx.en.txt` の該当行（`行番号|英文`）を直す。行番号は日本語版 .ks の行番号。
  3. `python tools/i18n_ks.py merge public/scenarios/xxx.ks translations/xxx.en.txt public/scenarios/en/xxx.ks`
  4. `npm run check:i18n` で構造と日本語の取り残しを確認
- 英文は `[` `#` `;` `*` で始めない（タグ・話者・コメント・ラベルとして解釈される）。`&f.main_name` の直後に英字を続けない。
- 訳語の基準：ナレーションは括弧なしの地の文、主人公の心の声だけ `(...)`。美羽の「先輩」は senpai、「ちゃん」は -chan のまま（ルートの主題なので）。エンディング表記は `(GOOD END — "タイトル")`。

## フラグ

- `[eval exp="f.xxx = true"]` と `[if exp="f.xxx"]` の真偽フラグだけを使う（数値比較はエンジン側で不安定）。
